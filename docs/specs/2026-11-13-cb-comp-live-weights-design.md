# P0.4 (#25): live-веса ИПЦ в `load_weights` — протокол

> **Пункт:** `key-rate/phase-4-cb-comp-88-groups-live`, зонтик [#419](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/419), P0.4 [#479](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/479), ML-часть [#25](https://github.com/kmlebedev/bi-ml-models/issues/25), `role:ml`. Go-часть — PR [clickhouse-import-rosstat#481](https://github.com/kmlebedev/clickhouse-import-rosstat/pull/481) (merged), замена весов 2026 — [#569](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/569) (merged).
> **Статус:** протокол записан **до прогона**. Правило источника, фолбэка и гейт не меняются после того, как увидены числа.
> **Границы:** товарная книга 2026 (`CPR_Tov_RF_2004-2026.xlsx`) недоступна (404), поэтому витрина в dev заполнена из архивных копий книг (2025-винтаж товаров, 2026-винтаж групп) — это провенанс данных, а не приёмка источника.

## 1. Гипотеза

Витрина `v_rosstat_cpi_weights` (main, импортёр `rosstat_cpi_weights`) — достаточный live-источник годовых весов ИПЦ: live-путь `load_weights` воспроизводит архив CB_COMP 2016–2024 до машинной точности и даёт веса 2025–2026 (архив кончается 2024).

Проверяемые следствия:

1. веса 2016–2024 совпадают с архивом: `max |Δ| ≤ 1e-12` по 88 группам и ЖКУ `9470` на пересечении кодов;
2. для месяцев 2026 берётся вес 2025, а не фолбэк 2024;
3. повтор Task 9 на `--weights live` даёт те же числа, что `--weights archive` на 2019–2024;
4. покрытие весов 2025–2026 ≥ 0,85.

## 2. Контракт витрины (main, PR #481)

| Колонка | Смысл |
|---|---|
| `year` | год структуры расходов (лист книги) |
| `variant` | `''` или `before-2022-04-01` / `from-2022-04-01` (две публикации 2022) |
| `source_file` | `CPR_tov_RF` — товары (услуги)-представители, коды во все годы; `CPR_Gr-Tov-RF` — группы (2016–2024 без кодов, `code='name:…'`) |
| `level` | уровень иерархии из файла (0 — файл не даёт) |
| `code` | код позиции (`111`, `930.АГ`, `2`, …) |
| `name` | название позиции на год |
| `weight` | **проценты** структуры потребительских расходов (не доли) |

Свойства, на которые опирается загрузчик: сумма товарного листа 99,1–99,2 % (объединённая группа «Воздушный и железнодорожный транспорт» публикуется одной строкой, `9260`/`9290` отдельно нет); итоговая строка в таблицу не пишется; `name:`-строки группового файла — не коды.

Провенанс dev-витрины на 2026-11-13: книги из Wayback (`CPR_Tov_RF_2004-2025.xlsx` 2025-04-04, `CPR_Gr-tov-RF_2001-2026.xlsx` 2026-09-09), `source_publications` не писалась; первый живой импорт в main перезапишет строки по ключу. Веса **2026** в витрине отсутствуют (товарной книги 2026 нет) — для месяцев 2027 они понадобятся, но правилу `M.year−1` сейчас не нужны.

## 3. Метод

`load_weights(archive, years, specs, source="archive"|"live", query=None)`:

- `archive` — прежний путь (default): архив CB_COMP 2016–2024, исторические прогоны и пины воспроизводятся без ClickHouse.
- `live` — витрина: **товарные** строки (`source_file='CPR_tov_RF'`, у них есть коды во все годы), проценты / 100 → доли, затем та же агрегация листьев по словарю года, что в архиве (`_aggregate_year_weights`), так что live-путь повторяет архивную арифметику, а не «похожую».
- **Словарь года** — `_dictionary_year`: сам год, иначе ближайший более ранний, иначе самый ранний; для 2025–2026 это словарь 2024. Коды, которых в словаре нет, выпадают из агрегата — это не ноль и не бэккаст, а строка отчёта `cb-comp-weights-check`.
- **Объединённая группа транспорта** — `LIVE_ARCHIVE_FALLBACK = (9260, 9290)`: в публичном товарном файле её нет; для 2016–2024 веса этих кодов берутся из архива (именованное исключение, перечисляется в отчёте), для 2025–2026 архива нет — коды выпадают (покрытие −0,0086), импутации нет.
- Групповой файл (`CPR_Gr-Tov-RF`) в live-пути **не** используется как источник весов групп: в 2016–2024 у него нет кодов; он остаётся сверкой по названиям (`cb_comp_weights_check`).
- **2022 — вариант-исключение** (`LIVE_ARCHIVE_YEARS = (2022,)`): публикация 2022 разбита на два листа («до 01.04» и «с 01.04»), и сырая live-агрегация расходится с архивом одной группой (`9540`, 0,0043). Модельный путь берёт 2022 из архива — пины Task 3/9 не переписываются; `cb-comp-weights-check` сравнивает **сырую** live-агрегацию (`archive_years=()`) и печатает расхождение отдельной строкой `variant_exception`. Выбор варианта live-2022 — решение владельца, подгонка запрещена.

**Матрица источников** (решение владельца 2026-11-01, не пересматривается):

| Скрипт | Источник | Почему |
|---|---|---|
| `cb_comp_h1_bs_combo.py` (Task 9), `cb_comp_88_live_gate.py` | `live` (default), `--weights archive` для регрессии | базовая модель; P0.4 |
| `cb_comp_live_bottomup.py`, `cb_comp_live_en.py` | `live` | окна оценки ≤ 2024, числа не меняются |
| `cb_comp_h1_shadow.py`, `cb_comp_groups_panel.py`, `cb_comp_h1_weekly*.py` | `archive` явно | замороженные P0.6/Task 4/4b: пины не переписываются до решения о перепиновке |

## 4. Гейт

1. **2016–2024 = архив** по 88 группам + `9470`: `max |Δ| ≤ 1e-12` на пересечении кодов. **2022 — вариант-исключение:** товарный файл 2025-винтажа содержит один лист 2022, групповой — два; сырое расхождение (на Wayback-копии — одна группа `9540`, 0,0043) печатается как `variant_exception` и в гейт не входит; модельный путь берёт 2022 из архива.
2. **2025–26:** сумма пары «товарный лист + объединённая группа транспорта» = 100 ± 0,5 (2025: 99,157 + 0,843; 2024: 99,141 + 0,859).
3. **Task 9:** `--weights archive` воспроизводит пины `combo3` 1,0348 / 0,9571 / 1,0102 / 0,8940 (R9a/R9b/R9c, G9 p = 0,0085); `--weights live` на `predictions.csv` — те же числа на 2019–2024 (допуск 1e-12; публикация в процентах не воспроизводит доли бит-в-бит).
4. **Покрытие** 2025–26 ≥ 0,85 (ожидается ≈ 0,918: 0,927 − 0,0086).

## 5. Stop-rules

- `max |Δ| > 1e-12` для 2016–2024 (кроме 2022-варианта) → `load_weights` не переключается, отрицательный результат в отчёт и PR, решение за владельцем.
- В live нет кода группы, который есть в архиве (кроме `803`/`930.АГ` до их года и `9260`/`9290` для 2025–26) → гейт не закрывается, список публикуется.
- Сумма пары 2025/2026 вне 100 ± 0,5 → отчёт, не «нормализуем».
- Витрина пуста/недоступна → офлайн-тесты готовы, live-часть «не проверено»; пункт не закрывается.

## 6. Что не проверено

- Веса **2026** (нужны месяцам 2027): товарной книги 2026 нет; когда появится, `cb-comp-weights-check` должен её увидеть и сверить.
- Живой источник в main (блокер [#571](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/571)): dev-витрина заполнена из архивных копий, а не из rosstat.gov.ru.
- Полный live-прогон Task 9 (352 CatBoost-модели): время прогона > 10 мин на загруженной машине; в этом пункте он выполняется, если укладывается в окно, иначе фиксируется как «не измерено» с причиной.
- Ревизии внутри года: месячная публикация `ipc_spr` показывает замену `9551` ОАЭ → `9547` Китай в 2026; на годовые веса из книг это не влияет, но состав кодов года может меняться.

## 7. Воспроизводимость

```bash
make cb-comp-weights-check-test

make cb-comp-h1-bs-combo-test
make cb-comp-h1-bs-combo ARGS="--archive <CB_COMP_ARCHIVE> --weights archive --out build/cb-comp-weights/archive"
make cb-comp-h1-bs-combo ARGS="--archive <CB_COMP_ARCHIVE> --weights live --out build/cb-comp-weights/live"
```

Артефакты: `build/cb-comp-weights/{check.json,coverage.json}`, `build/cb-comp-h1-bs-combo/{predictions.csv,result.json}`.
